# 大 STL 预览（0.1.1，2026-10-17）

此前大于 150 万面的 STL 会直接被拒绝；超过 128 MiB 的输入也无法进入渲染。
0.1.1 源码支持最多 1 GiB 的二进制/文本 STL，完整扫描顶点，按空间网格合并顶点、去除退化和重复面，生成最多 40 万面的显示网格。极端复杂模型在达到显示预算后使用固定种子的蓄水池抽样，避免只保留文件开头。缩略图可能损失细节；不会修改原始 STL。

传统版安装/修复后启动 `3DSTL.Refresh.exe`。它仅刷新当前用户桌面上已启用的模型格式，串行生成 256、96、48 像素缩略图并通知桌面更新。普通模型先处理；超过 150 万面的二进制 STL、超过 75 MiB 的文本 STL 放在队列末尾。刷新进程使用较低优先级；同一用户的多次刷新通过互斥量串行运行。进度和错误写入 `%LOCALAPPDATA%/3DSTL/thumbnail-refresh.log`。

这是桌面刷新队列的顺序，不是对 Windows 自己所有文件夹缩略图请求的全局调度。资源管理器主动请求大 STL 时也可以生成，渲染线程使用最低优先级，最多等待 180 秒。其他格式的输入大小、转换时间与复杂度限制未改变。

## 验证

- `tests/LargeStlTest.csproj`：普通模型先于大模型、超过 150 万面不再拒绝、显示面数有界、末尾几何保留、所有顶点均验证。
- 管理器 `--selftest`：临时注册表内验证修复、重复修复、恢复原关联。
- 实际 `头模.stl`：2,061,614 面，103,080,784 字节；生成成功，约 2.4 秒，测试进程峰值内存约 106 MiB。
- 实际 `HEAD SKETCH 8.stl`：文本 STL，823,025,126 字节；生成成功，约 13 秒，测试进程峰值内存约 133 MiB。

上述时间是本机独立渲染进程的单次测量，不含 Windows 缓存、IStream 临时文件复制及刷新其他尺寸的时间。

本机传统版组件已更新。实际 Windows 缩略图缓存接口验证：`28.stl` 排在 `头模.stl` 前面，两者的三个尺寸均成功。完整桌面刷新已作为后台进程启动。更新前的管理器和组件备份位于 `artifacts/large-model-preview/original-install-*`。

管理器“一键修复 / 安装”已增加即时忙碌状态、后台完成数量、当前文件、失败数量和最终汇总，以及“刷新日志”入口。同一会话已有刷新进程时不再重复启动。使用共享读取方式查看正在写入的日志，避免因文件占用而一直显示“准备中”。新增 `--selftest-ui` 在临时注册表验证真实按钮点击、异步修复完成、实时日志读取、进度及中英文失败汇总。本机界面已更新，并确认显示真实队列进度（25 / 33，失败 0）；原有后台刷新继续运行。

GitHub 0.1.1 ZIP 包含上述改动。已进入认证的 Microsoft Store 0.2.0.0 MSIX 尚未重新打包或提交。Store 源码的 STL 输入上限与等待时间已同步调整，但它没有传统版的桌面后台刷新队列。

## 尚未实现的性能优化

当前仍可能为不同缩略图尺寸重复解析/渲染模型。一次渲染复用多个尺寸、持久渲染缓存、3MF 复杂度提前判断、NAS 本地读取复用仍属后续优化，未包含在 0.1.1。OBJ 的 128 MiB/150 万面限制及 3MF 的 150 万面/每个 XML 180 MiB 限制保持不变，不能把成功返回内置图片等同于成功生成灰色几何预览。
